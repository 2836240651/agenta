## 1. 架构

```
Web (wizard) ──REST──► Server ──SyncSend──► Agent
                           │
                           ├─ listing_1688_workflows / sessions / image_jobs
                           ├─ images → AiEditImage → hyhacct
                           └─ publish → system_tasks（商家发品，非妙手）
```

| 层 | 职责 |
|----|------|
| Web | 四步 UI；只打 `/api/v1/listing1688/*` |
| Server | Workflow/Session/Collect/Images/Publish；Cookie 加密 |
| Agent | 采集登录+CDP+解析；M3 商家发品页自动化 |
| 1688- | 解析权威源；移植进 Agent sidecar，不在线依赖仓库 |

---

## 2. 表设计（MVP）

| 表 | 用途 |
|----|------|
| `listing_1688_workflows` | 向导主状态机、offer 快照、选定图索引 |
| `listing_1688_sessions` | 采集 Cookie（加密）+ 探针结果；商家会话标记可同表分 type 或另列 |
| `listing_1688_image_jobs` | 每 Slot 图优任务与结果 URL |

发品长任务：复用 `system_tasks`，`task_type` 用向导专用枚举（**禁止**复用妙手一键上架类型）。

## 3. API 前缀

`/api/v1/listing1688/`

| 组 | 示例 |
|----|------|
| Workflow | `POST /workflows` · `GET /workflows/:id` |
| Session | `POST .../session/open-login` · `.../confirm` · `.../validate` |
| Collect | `POST .../collect` · `.../collect/retry` |
| Images | `.../images/generate|regenerate|select|use-original` |
| Publish | `POST .../publish` · `GET .../publish/status` |

与 v1 `/api/v1/listing/1688/*`（妙手一键）**物理隔离**。

## 4. Agent 协议

### 采集（M1，对齐 SyncSend）

| 协议 | 作用 |
|------|------|
| 打开登录页 | 导航 1688 登录 |
| 导出 Cookie | 回传加密前明文由 Server 落库加密 |
| 探针 | 调 `sycm.1688.com/ms/common/information.json` |
| FetchOffer | CDP 取 HTML → 本地解析（移植 1688-）|

### 商家发品（M3，新建）

| 要点 | 说明 |
|------|------|
| 协议名 | 待 M3 方案定稿（如 `Listing1688SellerPublish`） |
| 输入 | 标题、选定图 URL、SKU/价格草稿 |
| 行为 | 打开商家发品页 → 填表 → 提交 |
| 输出 | 成功 offerId / 失败码 |
| **禁止** | 调妙手 `ProductIssue`、`alibaba_collect_box` |

## 5. 采集解析移植

| 源文件（1688-） | 用途 |
|-----------------|------|
| `fetch_1688_offer.py` | CDP/上下文取详情 HTML、字段抽取 |
| 相关解析工具/常量 | 标题、图、SKU、价格 |

移植策略：复制进 Agent 可执行侧（Python sidecar 或等价），单测对齐样例 HTML；**禁止**从零重写字段逻辑。

成功门槛（C4）：`title` + ≥1 `image` + `sku`。

## 8. 错误枚举（示意）

| 码 | 场景 |
|----|------|
| `SESSION_INVALID` | 采集探针失败 |
| `COLLECT_NEED_LOGIN` | 需重新登录采集 |
| `COLLECT_CAPTCHA` | 滑块/验证码 |
| `COLLECT_PARSE_FAIL` | 解析未达 C4 |
| `IMAGES_NOT_READY` | 未全选定 |
| `SELLER_SESSION_INVALID` | 商家未登录 |
| `PUBLISH_FAILED` | 发品页自动化失败 |
| `AGENT_OFFLINE` | Agent 不在线 |

## 10. M3 依赖

商家发品页自动化须单独方案后再编码，至少包含：

1. 发品入口 URL / 导航路径  
2. 字段映射（标题、主副图、SKU）  
3. 成功判定（列表可见 / offerId）  
4. 选择器集中配置与改版应对  

在方案未批前，Server/Agent 可留 Publish 接口空壳与枚举，**不得**接妙手冒充成功。
