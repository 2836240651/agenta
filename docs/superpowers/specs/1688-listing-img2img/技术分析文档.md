## 2. 目标架构（最小）

```
Web(1688-auto-upload)
  └─ POST product_issue (platform=1688, send 含 peer_url)
       └─ Server Listing1688Orchestrator（新建薄封装）
            ├─ CollectPeerImages（Onebound）
            ├─ Img2Img（v1 一键：`AiEditImage`→grsai；**非**向导路径）
            ├─ PersistAudit（新表）
            └─ AsyncSend Agent (protocol=product_issue)
                 └─ AlibabaFactory.ProductIssue（妙手导入）
```

**为何旁路封装而不是直接改 `RunProductIssue` 中段？**  
现网 `RunProductIssue` 强绑定「五场景图 + 三语标题」。1688 采集图优是「N 张商品图 edits」，硬塞会破坏 Temu。推荐：

```go
// tasks/proto_listing_1688.go
func (t *Task) RunListing1688(ctx manager.TaskContext) error
```

在任务分发处：`if platform == 1688 && hasPeerURL { RunListing1688 } else { RunProductIssue }`。  
**禁止**在 `RunProductIssue` 内用大量 `if platform==1688` 缠绕现有逻辑。

## 4. 错误枚举（必做）

新建 `commander-server-.../internal/constants/listing_1688_error.go`：

```go
package constants

// Listing1688ErrorCode 1688 采集图优上架错误码（稳定契约，供 Web 映射文案）
type Listing1688ErrorCode string

const (
	Listing1688ErrInvalidPeerURL      Listing1688ErrorCode = "LISTING_1688_INVALID_PEER_URL"
	Listing1688ErrCollectFailed       Listing1688ErrorCode = "LISTING_1688_COLLECT_FAILED"
	Listing1688ErrCollectNoImage      Listing1688ErrorCode = "LISTING_1688_COLLECT_NO_IMAGE"
	Listing1688ErrImg2ImgFailed       Listing1688ErrorCode = "LISTING_1688_IMG2IMG_FAILED"
	Listing1688ErrImg2ImgPartialFail  Listing1688ErrorCode = "LISTING_1688_IMG2IMG_PARTIAL_FAIL"
	Listing1688ErrAgentOffline        Listing1688ErrorCode = "LISTING_1688_AGENT_OFFLINE"
	Listing1688ErrPublishFailed       Listing1688ErrorCode = "LISTING_1688_PUBLISH_FAILED"
	Listing1688ErrPublishUnsupported  Listing1688ErrorCode = "LISTING_1688_PUBLISH_UNSUPPORTED"
	Listing1688ErrInternal            Listing1688ErrorCode = "LISTING_1688_INTERNAL"
)
```

Agent 侧对用户可见错误：优先回传同一枚举字符串（或 Server 在收 Receive 时归一）。  
**禁止**仅用 `fmt.Errorf("xxx失败")` 作为唯一对外契约。

Web：在现有 toast / 失败列表上增加 `error_code → i18n key` 映射表（小 map 即可）。

## 5. API / 协议

### 5.1 复用现有

- `POST /api/v1/agent/product_issue`（或现网等价路径）  
- `POST /api/v1/agent/task_list`  
- 协议：`constants.ProtocolProductIssue`

### 5.2 Send 载荷扩展（最小字段）

在现有 `ProductIssue` toc 上 **增量**（json 兼容）：

```json
{
  "peer_url": "https://detail.1688.com/offer/xxxx.html",
  "enable_img2img": true,
  "source_images": [],
  "images": []
}
```

其它平台不传 `peer_url` 时行为不变。

### 5.3 不新建 REST「大而全」资源

除非产品强制，MVP **不**单独开 `/api/v1/listing_1688/*` CRUD 全家桶；审计读写可挂在任务详情或一个极简 `listing_1688_job_get`。

## 6. Agent 实现要点

`AlibabaFactory.ProductIssue`：

1. 校验 `Images` 全部 success 且为 http(s)（复用 `ExtractProductIssueCarouselURLs` 思路，可抽到 `utils` 或平台无关函数）。  
2. 按 **妙手 1688 导入** 最小路径实现（优先对照抓包；结构可参考 AE 的 xlsx→OSS→import，但 **不得** 直接调用 AE / `AliExpressFactory` 专用 API；1688 ≠ 速卖通）。  
3. 若接口未就绪：联调可暂返 `LISTING_1688_PUBLISH_UNSUPPORTED`；**产品已确认 MVP 必须打通**，不得以此作为验收通过。

`ProductIssuePrecheck`：可继续「暂不做店小秘 Token 预检」，或增加「妙手登录态」检查（有则做，无则保持现状）。

## 10. 复杂度红线

禁止：

- 通用「采集引擎框架」  
- 多级状态机库  
- 为 1688 复制一整份 `RunProductIssue`  
- 前端新 UI 组件库

- 1 个编排文件 + 1 个采集辅助 + 1 个错误枚举 + 1 张表 + Agent 工厂填充 + Web 一个输入区块
