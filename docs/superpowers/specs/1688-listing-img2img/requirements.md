# 需求分析：1688 采集图优再上架

**日期**：2026-07-20  
**对齐设计**：[`../2026-07-20-1688-listing-img2img-design.md`](../2026-07-20-1688-listing-img2img-design.md)  
**落地**：Commander 三端（Web / Server / Agent）

---

## 1. 背景与问题

### 1.1 业务问题

- 现状：妙手 ERP 采集同行链接 → **原图**直接上 1688。  
- 诉求：采集得到的主图、副图先经 **图生图** 更新，再上架。  
- 工程诉求：统一到当前项目的 1688 上架逻辑；没有则新建模块；**UI 复用**；报错用枚举；表按需新增；**不影响既有功能**；最小实现。

### 1.2 系统问题

- Agent `AlibabaFactory` 上架未实现。  
- 业务上架发生在系统外（妙手），与 Commander 自动上架（Temu/AE）割裂。  
- 图生图能力已存在，但未接到「1688 采集 → 上架」链路上。

---

## 2. 必须验证的假设

| ID | 假设 | MVP 内如何验证 |
|----|------|----------------|
| H1 | Onebound（或等价）可按同行链接/ID 拉到主图+副图 URL | 单测 + 1 条真实链接联调 |
| H2 | 现有 AI 生图可对 1688 商品图批量 edits 成功 | 复用 `produce_images` / `AiEditImage` 跑通 ≥1 单 |
| H3 | 妙手存在可用的 **1688** 导入/发品接口（结构可参考 AE，但接口与工厂必须独立） | 抓包/对照文档 + Agent 联调；**MVP 必须打通** |
| H4 | Web `/1688-auto-upload` 可在不改 Temu 布局的前提下增加链接入口 | 平台分支 UI 开关验证 |

H3 不成立时：图优可先交付联调，但 **不得**将「仅素材就绪 / PUBLISH_UNSUPPORTED」签署为 MVP 完成；须继续打通妙手 1688 导入。

---

## 3. 范围

### 3.1 必做（MVP）

1. 同行链接（或 num_iid）采集主图 + 副图  
2. 对采集图执行图生图，写回任务载荷  
3. 新增错误枚举与任务失败映射  
4. 新增审计表（采集源、原图、优图、状态）  
5. 实现或明确降级 `AlibabaFactory.ProductIssue`  
6. Web 复用自动上架页，增加 1688 专用输入（链接）  
7. 回归：Temu / AE 冒烟不被破坏

### 3.2 明确不做（MVP）

- 智能选品、竞品分析看板  
- 官方 1688 OpenAPI 直发（无妙手）  
- 新设计一套与 `auto-upload` 平行的页面体系  
- 修改其它平台生图张数 / 提示词策略  
- 生产级多账号并发队列

### 3.3 二期预留

- 官方 API 发品旁路  
- Excel 批量同行链接  
- 图优 prompt 模板管理后台  
- 部分失败重试单张图

---

## 4. 角色与用户故事

| 角色 | 诉求 |
|------|------|
| 1688 运营 | 贴链接 → 自动图优 → 上架，少手工下图改图 |
| 工程 | 复用现有协议与 UI，平台隔离，可维护 |
| 测试 | 有枚举可断言，有回归门闸 |

**用户故事**

1. 作为运营，我在 `/1688-auto-upload` 粘贴同行链接并选择 Agent/店铺，提交后能看到任务进入处理中。  
2. 作为运营，任务成功后商品图已是图优结果（或任务明确失败原因）。  
3. 作为工程，Temu 上架流程在本次改动后冒烟仍通过。  
4. 作为测试，任意失败都能对应到稳定错误码，而不是模糊字符串。

---

## 5. 输入与产出

### 5.1 输入

- `peer_url` 或 `num_iid`  
- `agent_id` / `shop_id`（与现网一致）  
- 可选：`enable_img2img`（默认 true）  
- 可选：固定 prompt（配置项，非运营随意输入也可接受）

### 5.2 产出

- Agent 任务状态 success / failed  
- 审计表行：原图列表、优图列表、错误码  
- （若 H3 成立）妙手/1688 侧可见商品

---

## 6. 验收标准

1. **主路径**：合法链接 → 采集成功 → 图优成功 → **妙手 1688 上架成功**（任务 success；妙手/1688 侧可见）。  
   - `LISTING_1688_PUBLISH_UNSUPPORTED` 仅作联调失败态，**不计入** MVP 验收通过。
2. **图优有效**：优图 URL 与原图不同；抽检外观有改动。  
3. **失败可诊断**：无效链接、无图、图优失败、Agent 离线、发布失败均有枚举。  
4. **无回归**：Temu / 速卖通各至少 1 条既有冒烟通过。  
5. **无轮子**：不新增第二套任务列表组件；1688 生图复用 `produce_images`，禁止另开 Lyncr 业务口。

---

## 7. 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 妙手 1688 接口未知 | 上架不通 | 分阶段：先图优，后发布 |
| 采集接口限流 | 批量失败 | MVP 单链为主；限流错误码 |
| 图优成本/耗时 | 体验差 | 进度文案；副图上限 |
| 误改公共流水线 | 全平台事故 | 平台分支 + 回归门闸 |

---

## 8. 成功定义（一句话）

运营在 Commander 内用同行链接完成「采集 → 图优 →（妙手）上架」，失败有枚举，且不影响其它平台上架。
