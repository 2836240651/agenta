## 4. 用例清单

### 4.1 登录（L2）

#### TC-LOGIN-001 首次登录成功并保存状态

- **目标**：login 落盘有效 storage_state  
- **前置**：无 `cookies/csp_demo.json`（或已备份删除）  
- **步骤**：`ae-csp login --account demo` → 有头浏览器人工登录 → 等待成功  
- **预期**：生成非空 `cookies/csp_demo.json`；退出码 0；无 `--headless` 参数可用（或文档明确不支持）

#### TC-LOGIN-002 重复登录覆盖旧态

- **前置**：已有 cookie 文件；记录 mtime/hash  
- **步骤**：再次 login 并完成登录  
- **预期**：文件被更新；后续 check 仍可通过

#### TC-LOGIN-003 未完成登录即关闭浏览器

- **步骤**：login 后未登录直接关浏览器/超时  
- **预期**：非 0 退出；不留下「已登录成功」误导态（无新成功文件或明确失败）

#### TC-LOGIN-004 按账号 URL 覆盖

- **前置**：`accounts/demo.yaml` 使用店铺 A 的 login_url  
- **步骤**：login  
- **预期**：浏览器打开的首跳/回跳与配置一致（非另一店铺 channel）；登录后 check 使用同账号 publish_url

---

### 4.2 校验（L2）

#### TC-CHECK-001 有效态通过

- **前置**：login 成功  
- **步骤**：`ae-csp check --account demo`  
- **预期**：退出码 0；停留在 CSP 发品/后台相关 URL；无登录文案

#### TC-CHECK-002 缺失 cookie

- **前置**：删除 cookie 文件  
- **步骤**：check  
- **预期**：退出码 2；提示先 login

#### TC-CHECK-003 过期 / 伪造 cookie

- **前置**：篡改或使用过期 storage_state  
- **步骤**：check  
- **预期**：退出码 2；提示重新 login

---

### 4.3 抓包（L2）

#### TC-CAPTURE-001 手点发品录到关键请求

- **前置**：check 通过  
- **步骤**：`ae-csp capture --account demo` → 完整手建一品并提交 → 结束 capture  
- **预期**：session 含 `meta.json`、`requests.jsonl`、`filtered.json`；filtered 中有与 product/sku/upload/publish 等相关成功请求

#### TC-CAPTURE-002 filtered 完整 body

- **前置**：TC-CAPTURE-001  
- **步骤**：抽查 filtered 中至少 2 条业务 POST/PUT  
- **预期**：request/response body 为完整 JSON 或 form，而非截断摘要；jsonl 中对应条目允许截断

#### TC-CAPTURE-003 静态资源过滤

- **步骤**：capture 期间正常加载页面  
- **预期**：filtered 不以 js/css/png/font 为主；或明确不计为候选

#### TC-CAPTURE-004 可选 HAR

- **步骤**：`capture --har`  
- **预期**：生成 har 文件；默认可不生成

---

### 4.4 接口固化门闸（L2 + 人工）

#### TC-GATE-001 M4 产物齐全

- **前置**：完成至少一轮有效 capture  
- **步骤**：工程整理并写入 `endpoints.py` + `docs/capture-notes.md`  
- **预期**：文档含调用顺序、关键头、成功判据；endpoints 可被 publish dry-run 引用  
- **说明**：本用例未通过则 **跳过** 所有 TC-PUBLISH-00x 真发用例（可标 Blocked）

---

### 4.5 Schema 与 Dry-run（L1/L2）

#### TC-SCHEMA-001 缺少必填字段失败

- **步骤**：publish 使用缺少 title 或 skus 的 JSON  
- **预期**：退出码 3；不发起业务写操作（或 dry-run 亦报错）

#### TC-SCHEMA-002 合法 demo.json 可解析

- **步骤**：加载 `products/demo.json`  
- **预期**：通过 schema 校验

#### TC-PUBLISH-DRY-001 dry-run 不写后台

- **前置**：TC-GATE-001 通过  
- **步骤**：记录 cookie 文件 hash → `publish --dry-run --from products/demo.json`  
- **预期**：退出码 0；打印将发请求摘要；后台无新商品；cookie 文件 hash **不变**（dry-run 禁止 RefreshCookie）

#### TC-API-001（可选）单接口诊断

- **前置**：check 通过；已知一需登录 URL（可来自 filtered）  
- **步骤**：`ae-csp api --account demo --method GET --url <URL>`（若已实现）  
- **预期**：返回可解释状态；摘要含 cookie/csrf 注入情况；**未实现本命令时本用例记 N/A，不阻 M6 签署**

---

### 4.6 发布回放（L2，依赖门闸）

#### TC-PUBLISH-001 真实回放创建可见商品

- **前置**：TC-GATE-001、check 通过、合法 demo.json  
- **步骤**：记录 cookie hash → `ae-csp publish --account demo --from products/demo.json`  
- **预期**：退出码 0；CSP 后台可见新建商品（草稿或已提交，与 capture-notes 语义一致）；cookie 文件 hash **更新**（仅成功时 RefreshCookie）

#### TC-PUBLISH-005 失败不回写 cookie

- **前置**：能稳定触发发布失败（如 schema 已过但业务必挂的 payload，或断网模拟至退出码 4）  
- **步骤**：记录 cookie hash → publish  
- **预期**：非 0 退出；cookie hash **不变**

#### TC-PUBLISH-002 无 cookie 时 publish

- **前置**：无 cookie  
- **步骤**：publish（非 dry-run）  
- **预期**：退出码 2；提示 login；后台无变化

#### TC-PUBLISH-003 业务校验失败不盲目重试

- **前置**：构造必触发平台业务错误的 payload（如非法类目，以实站为准）  
- **步骤**：publish  
- **预期**：退出码 3（或明确业务失败）；日志无无限重试；有限次数后停止

#### TC-PUBLISH-004 headless 开关仅影响 publish

- **步骤**：`publish --headless ...`（门闸已过）  
- **预期**：可无头执行回放；`login --headless` 若被调用应拒绝或不存在该参数

---

### 4.7 安全与隔离（L1）

#### TC-SEC-001 敏感路径不进 git

- **前置**：已产生 cookies/captures/真实 accounts yaml  
- **步骤**：`git status`  
- **预期**：上述路径不被列为待提交（除非误 force add）

#### TC-ACC-001 双账号 cookie 隔离

- **前置**：`demo` 与 `shop-b` 各 login 一次  
- **预期**：`cookies/csp_demo.json` 与 `cookies/csp_shop-b.json` 并存互不覆盖

#### TC-NFR-001 无第三方 ERP 域名

- **前置**：对一次成功 publish 抓本地日志或抓包旁证  
- **预期**：无 `91miaoshou.com` / `dianxiaomi.com` 业务调用

## 6. 门闸与用例依赖（防逻辑断点）

```text
LOGIN-001 → CHECK-001 → CAPTURE-001/002 → GATE-001
                                              ↓
                                    PUBLISH-DRY-001 → PUBLISH-001
```

- `GATE-001` **Blocked** ⇒ `PUBLISH-001` / `PUBLISH-003` / `PUBLISH-004` 标 **Blocked**，不得记 Pass  
- 设计验收标准 4 与本文件 TC-PUBLISH-001 绑定，且依赖 GATE-001

## 7. 缺陷分级建议

| 级别 | 示例 |
|------|------|
| P0 | 无法 login；filtered 无完整 body；未门闸却宣称 publish 成功；cookie 进 git |
| P1 | check 误判；publish 业务失败无明确码；账号 URL 串店 |
| P2 | har 可选失败；日志过噪；限速默认不适 |
