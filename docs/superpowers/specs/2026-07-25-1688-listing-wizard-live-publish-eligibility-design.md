# 1688 向导真实发布资格与验收设计

**日期**：2026-07-25
**状态**：待用户审阅
**权威**：`docs/superpowers/specs/1688-listing-wizard-v2/README.md`
**范围**：场景 A，自家 1688 商家后台自动化发品

## 1. 决策

用户确认采用**直接真实发布**：通过资格预检和完整表单校验后，Agent 点击 1688 最终发布按钮；不增加人工授权闸门，不调用妙手、店小秘或其他第三方发品通道。

当前 Agent 浏览器 Profile 的实际审查结果是：发品路由被引导至 `cxt.1688.com/tp_service.html`，页面明确提示当前登录的是个人账号。该账号不具备企业店发品资格；这是平台前置条件，不应被误报为浏览器已具备商家发布能力。

## 2. Agent 资格预检

1. 探针直接访问卖家发品路由，而不是只访问 `work.1688.com/` 首页。
2. 探针必须等待并识别实际发品页、发品 iframe 或类目选择控件。
3. 下列任一结果返回 `SELLER_ACCOUNT_INELIGIBLE`，且不得保存 `seller_ok`：
   - 最终 URL 或任意可见 iframe 属于 `cxt.1688.com`；
   - 页面包含“个人账号”“商家自助开店”“只有1688企业账号”“注册店铺账号”等开店引导文案；
   - 未识别到卖家发品页或类目入口。
4. 登录页仍返回 `SELLER_SESSION_INVALID`；页面验证码返回可重试的 `PUBLISH_FAILED`。

## 3. 真实发布自动化

真实发布按顺序执行，任一必需步骤未验证通过即停止并返回可诊断错误，绝不点击最终发布：

1. 选择商品类目，并验证已进入该类目的发布表单；
2. 枚举并填写平台标记的必填属性；缺少映射时返回属性名称与 `PUBLISH_REQUIRED_FIELD_MISSING`；
3. 填写标题、选定图片、所有 SKU/规格和价格；
4. 填写详情描述、发货/物流及平台要求的其他必填字段；
5. 点击最终发布按钮；
6. 轮询平台结果，仅在获得非空 `offer_id` 且页面明确显示“发布成功”或“审核中”时返回成功。

类目属性、物流和详情的结构以真实卖家企业店页面 DOM 为准；当前个人账号无法生成该表单，不能用买家或开店页选择器替代。

## 4. Server 成功判定

`published` 仅在 Agent 返回以下全部证据时写入：

- `ok=true`；
- `submitted=true`；
- `images_set >= 1`；
- `title_filled=true`；
- `offer_id` 非空；
- `platform_status` 为 `published` 或 `auditing`；
- `success_hint=true`。

任何弱提示、空 `offer_id`、仅点击提交、仅填标题或保存草稿均不可使 Workflow 进入 `published`。失败时保持可重试状态并写入平台错误详情。

## 5. 验收与测试

- Agent HTML fixture：有效卖家发品页通过；登录页、买家工作台、`cxt.1688.com`、个人账号开店页均失败且错误码准确。
- Agent 自动化单元测试：未完成类目/必填字段/详情/物流时不调用最终提交；成功路径仅接受非空 `offer_id` 和明确平台状态。
- Server 单元测试：空 `offer_id`、未知状态、弱 success hint、仅草稿/仅 submitted 均不写 `published`。
- 企业店账号可用后执行真实环境回归：以无价值测试商品完成一次发布，记录 `offer_id`，并在商品管理“审核中”或“销售中”可查。

## 6. 非目标

- 不绕过企业账号、入驻、类目资质、品牌授权、保证金、验证码或平台风控；
- 不将当前个人账号伪装为企业店；
- 不部署到远程服务器；本任务仅修改本地代码并按仓库规则提交到 GitHub。
