# 1688 采集图优再上架 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Commander 三端跑通「粘贴 1688 同行链接 → Onebound 采集主图/副图 → AI 生图（`/api/v1/ai/produce_images` 同源，副图上限 9）→ Agent 经妙手 1688 导入上架」，且不影响 Temu / 速卖通 / Ozon。

**Architecture:** Web `/1688-auto-upload` 增加链接输入；Server 用旁路 `RunListing1688`（**不**改 `RunProductIssue` 五场景逻辑）编排采集+图优+审计表；Agent 在 `AlibabaFactory.ProductIssue` 实现妙手 **1688** 导入（结构可参考 AE，禁止调用 AE API）。

**Tech Stack:** Vue3 + Gin/GORM/PostgreSQL + Wails Agent Go；**grsai** 图生图（经 produce_images / AiEditImage）；Onebound；妙手 ERP  
**生图硬性**：上游 **grsai**；1688 **禁止** Lyncr；Temu 轮播与 1688 隔离。

**Spec:** `docs/superpowers/specs/2026-07-20-1688-listing-img2img-design.md`  
**Doc pack:** `docs/superpowers/specs/1688-listing-img2img/`

## Global Constraints

- **平台隔离（硬性）**：1688（国内）≠ 速卖通 AliExpress（国外）。禁止混用工厂、Resty、xlsx 列映射、导入 API。
- MVP **必须**打通妙手 **1688** 导入；`LISTING_1688_PUBLISH_UNSUPPORTED` 仅联调应急，**不是**验收通过口径。
- 入口：**粘贴同行链接**；Excel 批量同行链接 = 二期。
- 副图图优上限常量：**9**（`Listing1688MaxExtraImages = 9`）；主图必做图优。
- 禁止在 `RunProductIssue` 内堆 `if platform==1688` 缠绕 Temu 五场景逻辑；新建 `RunListing1688`。
- 禁止改 `ai_images` / `reptile_product` 表语义；新表 `listing_1688_jobs`。
- 错误对外用枚举 `LISTING_1688_*`，禁止仅靠模糊中文字符串。
- 密钥、Cookie、真实同行链接 **禁止** 提交 git。
- PowerShell：用 `;` 不用 `&&`。
- 收工写 `开发文档.md`；commit/push 按用户明确要求执行。

- [ ] **Step 2: Implement `RunListing1688`**

顺序：
1. 解析 `peerUrl` → num_iid  
2. Onebound 采集 → `source_images`；写审计 processing  
3. `enable_img2img!=false`：对每张图构造 `ProductIssueImage{Prompt: 固定保真 prompt, Status: processing}`，调 `utils.AiEditImage`（参考图用该张原图字节；比例默认正方形）；**禁止**调用 `runLyncrProductCarousel` / 业务侧点名 Lyncr

5. 成功：写 `optimized_images`；组装 payload（`ShopId` 来自原 Send；`Variants` 若为空可塞 1 个占位以满足 Agent 校验——以抓包后真实妙手字段为准，本步先保证 Images 齐全）  
6. Agent 离线 → `LISTING_1688_AGENT_OFFLINE`  
7. `AsyncSend` / 现有下发路径与 `RunProductIssue` 末尾一致
